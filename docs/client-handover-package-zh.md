# 客户交付包目录

这份文档用于正式交付客户时整理材料。建议每个客户建一个独立文件夹，把本页列出的内容按客户实际情况复制一份保存。

## 一、交付包建议结构

```text
客户名称-餐馆系统交付包/
├── 01-客户信息.md
├── 02-部署信息.md
├── 03-后台账号.md
├── 04-桌台二维码/
├── 05-菜单导入模板/
├── 06-打印助手配置/
├── 07-上线前检查记录.md
├── 08-客户验收确认.md
└── 09-售后维护记录.md
```

不要把真实密码、Supabase 密钥或 `print-agent/config.json` 上传到公开仓库。

## 二、需要交给客户的资料

建议交付：

- 线上网站地址
- 后台登录地址
- 后台账号邮箱
- 初始密码，建议客户首次使用后修改
- 桌台二维码 PDF 或图片
- 菜单 CSV 快速模板
- 打印助手客户指南
- 上线前检查清单
- 售后维护说明

不建议直接交付：

- Supabase service role key
- `.env.local`
- `print-agent/config.json`
- 数据库管理员密码
- GitHub 仓库写权限，除非客户明确购买源码交付

环境变量只记录“是否已配置”，不要在普通交付文档里明文写密钥。

```text

VITE_SUPABASE_PUBLISHABLE_KEY：已配置 / 未配置
DEEPSEEK_API_KEY：已配置 / 未使用
```

```text
老板账号：

是否已测试登录：是 / 否
是否提醒客户修改密码：是 / 否
```

密码建议通过微信、短信或当面单独告知，不建议写在交付包里长期保存。

## 六、桌台二维码交付

每张桌台二维码建议命名：

```text
Table-01.png
Table-02.png
Table-03.png
```

交付前确认：

- [ ] 二维码指向当前正式域名
- [ ] 桌号和实际桌面一致
- [ ] 旧二维码已废弃或不会混用
- [ ] 手机扫码能进入正确桌台
- [ ] 二维码打印清晰，距离 20-30cm 可扫码

## 七、菜单导入模板

交付时建议准备：

- 快速菜单 CSV 模板
- 完整菜单 CSV 模板
- 客户当前菜单备份

提醒客户：

- 第一行是系统字段名，不要改成中文。
- 第二行中文说明会被系统自动跳过。
- 图片 URL 可以后补。
- 如果只是临时停售，用“下架”或“售罄”，不要直接隐藏。

## 八、打印助手交付

交付前确认：

- [ ] Windows 测试页可打印
- [ ] `pnpm print-agent -- --setup` 已配置
- [ ] `pnpm print-agent -- --test-print` 可出纸
- [ ] 新扫码订单可自动打印
- [ ] 新 POS 订单可自动打印
- [ ] 客户知道不能关闭打印助手窗口
- [ ] 如需开机自启，已执行 `pnpm print-agent -- --install-startup`

打印助手详细说明见：

- `docs/print-agent-client-guide-zh.md`
- `print-agent/README.md`

## 九、上线验收

正式交付前使用：

- `docs/pre-launch-checklist-zh.md`
- `docs/client-install-checklist-zh.md`
- `docs/client-acceptance-form-zh.md`

建议让客户现场确认：

- 手机扫码点餐能用
- 后台能看到订单
- 厨房小票能打印
- POS 前台点单能用
- 菜单、价格、图片和营业信息正确
- 知道厨房小票不是正式税务发票

## 十、售后维护记录

建议每次维护都记录：

```text
日期：
客户反馈：
处理内容：
是否远程 / 现场：
是否影响营业：
后续待办：
```

这样以后客户多了，不会靠记忆维护，交付会更像正式产品。
