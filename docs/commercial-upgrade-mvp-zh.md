# 餐馆系统商业增强 MVP 说明

本文档用于说明当前版本在“正式商业交付版”方向上的增强范围，方便给客户演示、部署和后续报价。

## 已落地增强

### 1. 新客户开店检查

后台 `系统设置` 中新增“商业交付检查”，用于上线前确认：

- 餐馆名称、地址、营业时间是否已配置
- 联系电话、WhatsApp、Instagram、地图入口是否已配置
- 菜单分类和菜品是否已导入
- 桌台二维码是否已创建
- 现金 / POS 付款方式是否至少启用一种
- 后台实时订单连接是否正常

该检查只读，不会修改数据库。

### 2. CSV 菜单导入预检

后台菜品管理的 CSV 导入现在会在写入数据库前显示摘要：

- 预计新增菜品数量
- 预计更新菜品数量
- 预计新增分类数量
- 缺少图片的菜品数量
- 缺少英文 / 希腊语翻译的菜品数量
- options JSON 错误和关键字段风险

这样适合正式餐馆一次性导入几十到几百道菜时提前发现问题。

### 3. AI 菜单补全状态

系统健康检查会显示：

- DeepSeek 菜单 AI 是否已配置
- OpenAI 图片生成是否已配置

当前后台菜品编辑已支持：

- 根据菜名补全中文 / 英文 / 希腊语描述
- 生成图片提示词
- 在配置 `OPENAI_API_KEY` 后生成菜品图片

已有字段不会被 AI 自动覆盖。

### 4. 本地打印助手交付说明与状态回传

后台 `系统设置` 新增“本地自动打印助手”说明和“打印助手状态”，明确：

- 适合前台 Windows 电脑或 Windows 平板
- 需要先安装打印机驱动并确认 Windows 测试页能打印
- 打印助手用于监听新订单并打印厨房小票
- 电脑关机、程序关闭或网络断开时不会自动打印
- 厨房小票不是希腊税务正式发票
- 打印助手会回传最后在线时间、最后打印时间、最近错误和打印机名称

正式税务收据仍由餐馆原收银机 / POS 开具。

### 5. 员工权限建议

后台新增“员工权限建议”，当前数据库支持：

- 老板 / 管理员：设置、菜单、桌台、数据备份、归档删除
- 前台员工：订单、POS 点单、确认收款、清桌
- 厨房：只读查看订单和小票预览，不开放收款、清桌、菜单、桌台和系统设置

老客户需要执行 `supabase/patches-archive/2026-07-03-print-agent-status-kitchen-role.sql` 后才支持 `kitchen` 角色和打印助手状态回传。

### 6. 运行状态提示

后台系统状态会显示：

- 数据库连接
- 基础配置
- Realtime 连接
- DeepSeek 菜单 AI
- OpenAI 图片生成

用于判断“为什么后台收不到订单 / AI 不能用 / 图片不能生成”等常见问题。

### 7. 缺图菜品批量处理

后台菜品管理新增：

- 缺图片统计
- “只看缺图”筛选
- “缺图清单”导出 CSV

清单包含分类、菜名、描述和建议图片提示词，适合交给老板补图、摄影师拍图，或后续批量接入 AI 图片生成。

## 仍建议后续做的正式商业功能

### 图形化打印助手

当前打印助手已有本地设置页和安装包方向，但下一步建议做完整桌面体验：

- 托盘常驻图标
- 正在监听 / 已断开 / 打印失败状态（后台已支持状态回传，桌面端可继续做托盘 UI）
- 最近打印订单列表
- 一键重打
- 自动启动状态可视化

### 更细分员工权限

当前已支持厨房只读角色。如果客户有更多分工，建议继续扩展数据库级权限：

- 管理员才能改设置和归档删除
- 员工只能处理订单、POS、收款和清桌
- 厨房账号只能看订单和打印状态
- 财务账号只能看收款统计和导出
- 经理账号能改菜单但不能改系统配置

这需要 Supabase SQL/RLS/RPC 专项升级，不建议夹在 UI 优化中悄悄改。

### 菜品图片批量处理

适合 200+ 菜品的餐馆：

- 批量识别缺图菜品（已支持）
- 批量导出图片提示词（已支持）
- 批量生成或导入图片
- 按分类批量处理

### 客户安装向导

后续可以把后台开店检查做成真正向导：

1. 填餐馆资料
2. 导入菜单
3. 创建桌台
4. 配置付款方式
5. 测试下单
6. 测试打印

## 商用边界说明

- 本系统是餐馆官网、扫码点餐、后台管理和厨房小票系统。
- 厨房小票不等于希腊税务发票。
- 正式收据、刷卡支付和税务申报仍应由餐馆现有 POS / 收银机 / 会计系统处理。
- 如需对接希腊本地支付、税务或 AADE / myDATA，需要单独评估和报价。
